# 🛣️ Road Damage Detection with YOLO — Train, Compare, Deploy

End-to-end pipeline that **detects and localizes road damage** from images/video, compares
**three YOLO generations** (YOLOv5u, YOLOv8, YOLO11), tunes their hyperparameters, selects the best
model, and serves it through a **Streamlit** app.

| Class | Meaning |
|---|---|
| D00 | Longitudinal crack |
| D10 | Transverse crack |
| D20 | Alligator crack |
| D40 | Pothole |

## Pipeline overview

```
RDD2022 (VOC XML) ─► prepare_rdd2022 ─► train (baseline x3) ─► tune (GA, x3) ─► train (tuned x3)
                                                                                    │
 Streamlit app ◄── models/best.pt ◄── report (select best) ◄── evaluate (test split) ◄┘
```

## Quick start

```bash
git clone <your-repo-url> && cd road-damage-yolo
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
```

### 1. Dataset
Download **RDD2022** (Road Damage Detection 2022, CRDDC2022) and extract it so that
`RDD2022/<Country>/train/{images,annotations/xmls}` exists. (Also available on Kaggle.)

```bash
make data SRC_RDD=/path/to/RDD2022
# 80/10/10 random split, only D00/D10/D20/D40 kept → data/rdd2022_yolo/data.yaml
```
> The official RDD2022 *test* folders have no public labels, so the script builds its own
> train/val/test split from the labeled data (seed 42, reproducible).

### 2. Train, tune, evaluate
```bash
make train        EPOCHS=100 DEVICE=0       # baseline: yolov5su, yolov8s, yolo11s
make tune         TUNE_EPOCHS=30 TUNE_ITERS=50
make train-tuned  EPOCHS=100
make evaluate                               # test-split metrics + FPS + ONNX
make report                                 # tables, plots, selects models/best.pt
# or everything: make all
```
No GPU? Use `DEVICE=cpu` with fewer epochs/images, or run the same commands in Google Colab/Kaggle (free T4).

### 3. Run the app
```bash
make app            # → http://localhost:8501
# or
docker build -t road-damage-yolo . && docker run -p 8501:8501 road-damage-yolo
```

## Experimental design (for a fair comparison)
- **Models:** YOLOv5su, YOLOv8s, YOLO11s — all "small" variants, same Ultralytics training framework.
- **Same data, split, image size (640), epochs, seed, batch** for all models. Only the weights/architecture differ.
- **Hyperparameter tuning:** Ultralytics genetic algorithm (`model.tune`), search over
  `lr0, lrf, momentum, weight_decay, warmup_epochs, box, cls, dfl, hsv_h/s/v, degrees, translate, scale, fliplr, mosaic, mixup`
  with AdamW (see `src/tune.py`). The best set is stored in `configs/tuned/<model>.yaml` and used to re-train.
- **Selection:** the model/stage with the highest composite deployment score (default) or highest mAP50-95
  (`python -m src.report --select-by map5095`).

## Metrics (all measured on the held-out **test** split)
| Metric | How it is computed |
|---|---|
| mAP50 / mAP50-95 | Ultralytics validator, `conf=0.001` |
| Precision / Recall / F1 | Mean over classes at the best-F1 operating point (Ultralytics) |
| IoU | `mean_iou_tp`: mean IoU of true positives (class-matched, IoU≥0.5) at conf 0.25. `mean_iou_gt`: mean best same-class IoU per ground-truth box (0 if missed) |
| FPS / latency | Batch size 1, end-to-end (preprocess + inference + NMS), after warm-up, on the selected device **and** CPU |
| Model size | `.pt` file size (MB), parameters (M), GFLOPs; ONNX size (MB) |
| Deployment efficiency | ONNX CPU FPS + size + composite score `0.50·mAP50-95 + 0.25·FPS + 0.15·(1/size) + 0.10·IoU` (min-max normalised, weights editable in `src/report.py`) |

## Comparative analysis (fill in after running)
Use `results/COMPARISON.md` (auto-summary + per-class AP) and discuss:
1. **Accuracy:** which model has the best mAP50-95? Is the gap between generations large or within noise (consider multiple seeds)?
2. **Precision vs recall:** which model misses fewer damages (recall) vs raises fewer false alarms (precision)? Which matters more for road maintenance?
3. **Per-class behaviour:** thin, low-contrast cracks (D00/D10) are typically harder to localize than potholes (D40); check `ap50_*` columns and the IoU plot.
4. **Speed vs accuracy:** read `results/figures/tradeoff.png`; identify the Pareto-optimal models.
5. **Deployment efficiency:** model size, CPU FPS, ONNX speed — is it viable for edge devices/dashcams (≥ ~15 FPS)?
6. **Effect of tuning:** gain per model (reported automatically); did tuning help more for some architectures?
7. **Final choice** and justification, plus limitations (see below).

## Deployment app (Streamlit)
- Image upload (multiple), video upload (frame-by-frame streaming with live FPS), camera snapshot.
- Adjustable confidence / NMS IoU / inference size.
- Per-detection table (class, confidence, box, % image area), class-count chart, download annotated image.
- Loads `models/best.pt` (override with `MODEL_PATH` env var or the sidebar).

## Limitations & future work
- RDD2022 labels are noisy and differ between countries (domain shift); evaluate per country.
- Results come from one split/seed; report mean±std over several seeds for stronger claims.
- Possible extensions: larger models (m/l), TensorRT/INT8 quantization, tracking across video frames, severity estimation, GPS tagging.
